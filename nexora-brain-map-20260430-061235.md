## IMMEDIATE FIX PLAN

### Stage 1 — Freeze brain sprawl
- Do not delete files.
- Stop adding new `superbrain`, `autonomousEngine`, or `loop` files.
- Only `nexoraOrchestrator.ts` can make final decisions.

### Stage 2 — Make Phantom X a Nexora module
- Phantom X scans markets.
- Phantom X scores opportunities.
- Phantom X reports paper outcomes.
- Nexora makes final risk/action decisions.

### Stage 3 — Unify startup
- `server/index.ts` starts only one Nexora loop.
- Trading loops become controlled services called by Nexora or API.
- No duplicate auto-start loops.

### Stage 4 — Unify memory
- Trading memory should be bridged into `nexora_knowledge`, `nexora_decisions`, and `nexora_outcomes`.
- Keep Phantom X tables as specialist evidence tables, not separate brain memory.

### Stage 5 — Build finished app
- Admin Phantom X UI stays premium.
- Client Phantom X page uses same system but limited/compliance-safe.
- All Scan/Learn buttons call backend APIs.
- All decisions are logged through Nexora.
