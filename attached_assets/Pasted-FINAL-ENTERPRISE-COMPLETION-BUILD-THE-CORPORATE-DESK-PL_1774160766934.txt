STAGE 10 — NEXORA ADMIN COPILOT
==================================================

ADD A PERSISTENT NEXORA CHAT BUBBLE ACROSS THE ENTIRE ADMIN SIDE.

This is mandatory.

Nexora must function as a floating admin copilot that stays available from page to page across the admin experience.

REQUIREMENTS:

1. Persistent floating chat bubble
- visible across all admin pages
- anchored consistently bottom-right
- premium styling matching the platform
- minimized by default or intelligently stateful
- expands into a chat panel/modal/drawer
- must persist across route/page changes on the admin side

2. Route-aware context
Nexora must know what page/admin module the user is on, for example:
- referrals
- commissions
- partners
- intelligence
- settings
- dashboard

It should use current route/page context to give more useful help.

3. Data-aware admin assistant behavior
Nexora should be able to help with:
- summarising what is on the current screen
- explaining referral pipeline status
- identifying hot opportunities
- highlighting stale deals
- summarising partner performance
- explaining commission states
- suggesting next best admin action
- answering questions about current records if the data is available

4. Safe action model
Nexora may recommend actions, but must not silently mutate critical data without explicit user confirmation.
For example:
- OK to suggest "mark this as reviewing"
- OK to suggest "rerun AI scoring"
- OK to draft next actions
- NOT OK to silently mark deals paid/won/lost without explicit confirmation

5. UX requirements
- premium dark/gold styling matching admin
- clean, fast, minimal UI
- conversation history preserved during session
- does not obstruct primary admin actions
- mobile/tablet responsive if admin is viewed there
- supports open/close/minimise
- smooth transition across route changes

6. Functional requirements
- chat bubble available on every admin page
- chat panel receives current page context
- chat can call or query existing admin/intelligence data where appropriate
- chat uses real backend data or real available context
- no fake canned assistant pretending to know data it does not know
- if data is unavailable, Nexora must say so clearly

7. Suggested capabilities
- "Summarise this page"
- "What should I focus on first?"
- "Which referrals are hottest?"
- "Which deals are stale?"
- "Show commission risk areas"
- "What changed today?"
- "What should I follow up now?"

8. Implementation rule
If an existing Nexora/orchestrator/chat system already exists, upgrade and reuse it.
Do not create a disconnected second assistant if a usable one already exists.

9. Logging and documentation
Document:
- how Nexora is mounted globally in admin
- what context is passed into it
- what actions it can and cannot take
- any limitations
- any future upgrades needed

COMPLETION REQUIREMENTS FOR THIS STAGE:
- Nexora bubble appears across admin routes
- it survives page-to-page navigation
- it receives route context
- it can answer based on real current data/context
- it matches premium admin design
- it is documented fully
- it does not break admin performance or usability
