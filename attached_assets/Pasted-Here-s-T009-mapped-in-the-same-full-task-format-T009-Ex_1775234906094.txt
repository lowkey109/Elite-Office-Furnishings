⸻

T009: Execution Quality + Slippage Intelligence Layer
	•	Blocked By: [T003, T005, T007, T008]

⸻

Objective

Transform the trading system from:
	•	assuming clean fills and ideal exits

into:
	•	measuring execution quality
	•	tracking slippage vs expectation
	•	understanding where PnL is lost in execution
	•	feeding execution reality back into decisions, risk, and stress layers

⸻

T009 in one line

Expected trade → actual fill/exit → execution delta → slippage analysis → execution quality scoring → smarter assumptions

⸻

Build These Parts

1. Execution model layer

Introduce a realistic execution model for paper trades.

For each trade:
	•	expected entry price
	•	actual simulated entry price (based on real spread/slippage assumptions)
	•	expected exit price
	•	actual exit price
	•	slippage (entry + exit)

Important:
	•	still paper trading
	•	but no longer “perfect fills”

Inputs:
	•	bid/ask if available (from T003)
	•	spread estimates
	•	volatility context
	•	scenario flags (gap, fast move, etc.)

Suggested file:
	•	server/services/trading/executionModel.ts

⸻

2. Slippage tracking

Track slippage at trade level.

For each trade_outcome:
	•	expectedEntryPrice
	•	actualEntryPrice
	•	expectedExitPrice
	•	actualExitPrice
	•	entrySlippage
	•	exitSlippage
	•	totalSlippageImpact
	•	slippagePct

Store in DB.

⸻

3. Execution quality scoring

Score each trade’s execution quality.

Factors:
	•	slippage vs expected
	•	spread conditions
	•	volatility at entry/exit
	•	speed of movement
	•	gap conditions

Outputs:
	•	executionQualityScore (0–100)
	•	executionQualityLabel:
	•	excellent
	•	good
	•	acceptable
	•	poor
	•	failed

Suggested file:
	•	server/services/trading/executionQuality.ts

⸻

4. Execution analytics

Aggregate execution performance across:
	•	symbol (BTC vs ETH vs SOL vs XAUUSD)
	•	strategy
	•	volatility regime
	•	time of day
	•	entry type (breakout vs pullback)
	•	exit type (stop vs target vs timeout)

Metrics:
	•	avg slippage
	•	worst slippage
	•	slippage variance
	•	% of trades with poor execution
	•	execution-adjusted PnL vs theoretical PnL

Suggested file:
	•	server/services/trading/executionAnalytics.ts

⸻

5. Execution-adjusted performance

Update performance calculations to include:
	•	theoretical PnL (perfect fills)
	•	actual PnL (with slippage)
	•	execution drag (difference)

This becomes critical because:
	•	a strategy can look profitable in theory
	•	but fail in real execution conditions

⸻

6. Slippage profiles per asset

Define baseline expectations.

Examples:
	•	BTC → low slippage
	•	ETH → moderate
	•	SOL → higher
	•	XAUUSD → depends on feed/liquidity

Suggested table (optional):

execution_profiles
	•	id
	•	symbol
	•	avgSpread
	•	avgSlippage
	•	volatilityMultiplier
	•	lastUpdated

These profiles improve realism over time.

⸻

7. Stress integration

Connect to T008:
	•	stress scenarios should now include:
	•	slippage x2
	•	slippage x3
	•	spread widening

This allows:
	•	“what happens if exits are worse than expected?”

⸻

8. Allocation feedback loop

Connect to T007:
	•	if an asset consistently has poor execution:
	•	reduce allocation
	•	reduce size
	•	increase required confidence

Examples:
	•	SOL slippage too high → reduce max risk per trade
	•	breakout strategy slipping badly → tighten rules

Do NOT auto-change yet unless passing T006 guardrails.

⸻

9. Execution logging

Add table:

execution_logs
	•	id
	•	decisionId
	•	positionId
	•	symbol
	•	expectedEntry
	•	actualEntry
	•	expectedExit
	•	actualExit
	•	entrySlippage
	•	exitSlippage
	•	totalSlippage
	•	slippagePct
	•	executionQualityScore
	•	executionQualityLabel
	•	createdAt

⸻

10. Execution endpoint

Add endpoint:

GET /api/admin/trading/execution

Returns:
	•	slippage summary
	•	execution quality distribution
	•	worst execution cases
	•	execution-adjusted performance
	•	per-asset execution stats

⸻

11. Frontend execution panel

Extend trading monitor.

Show:
	•	avg slippage per asset
	•	execution quality distribution
	•	worst execution trades
	•	execution vs theoretical PnL
	•	slippage trends over time

Examples:
	•	BTC avg slippage: 0.08%
	•	SOL avg slippage: 0.42%
	•	execution drag: -6.3% of total PnL
