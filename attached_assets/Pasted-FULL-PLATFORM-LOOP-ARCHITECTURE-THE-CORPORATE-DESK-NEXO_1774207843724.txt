==================================================
CORE OBJECTIVE
==================================================

Loop the entire platform together so that:

- navigation connects to journeys
- journeys connect to AI reasoning
- AI reasoning connects to next actions
- next actions connect to lead records
- lead records connect to admin visibility
- admin visibility connects to follow-up and operational action
- user actions continuously enrich the system
- no major action happens in isolation

Everything must feed everything else in a controlled, structured way.

==================================================
LOOP RULES
==================================================

1. ROUTE LOOP
Every route must be connected into the system.
No page should exist as an isolated brochure page unless intentionally informational.
Each page must know:
- what journey it belongs to
- what service it represents
- what next actions are valid
- what data should be collected
- what Nexora should infer from activity on that page

2. CTA LOOP
Every CTA must:
- have a clear destination
- update user/session context
- feed Nexora a signal
- influence next-step recommendations
- never act as a dead button or isolated link

3. ASSISTANT LOOP
The assistant must be connected to:
- current route
- previous route
- session state
- user intent
- lead state
- form state
- uploaded files
- selected service
- Nexora decision outputs

It must not just answer questions.
It must feed and be fed by the rest of the platform.

4. LEAD LOOP
Any meaningful commercial action must create or update a lead/session record.

Examples:
- quote started
- quote submitted
- planner opened
- file uploaded
- strategy call clicked
- finance interest shown
- procurement enquiry made
- assistant used meaningfully
- user revisits key commercial pages
- user abandons a high-intent flow

The lead record must be enriched continuously, not recreated blindly.

5. ADMIN LOOP
Admin must receive:
- route journey
- detected intent
- selected services
- urgency signals
- AI summary
- recommended next best action
- blockers
- uploaded file presence
- quote/planner progress
- whether human follow-up is needed

Admin must not just receive raw form dumps.

6. QUOTE LOOP
Quote Builder must be connected to:
- Nexora
- lead records
- session context
- planner state if relevant
- product/service recommendations
- admin visibility
- next-step workflows

Starting a quote must affect the rest of the system.

7. PLANNER LOOP
AI Office Planner must connect to:
- uploaded files
- project scope
- Nexora reasoning
- quote recommendations
- walkthrough recommendations
- strategy recommendations
- admin notes

It must not operate as a standalone toy.

8. 3D WALKTHROUGH LOOP
3D Office Walkthrough page must connect to:
- device capability checks
- Nexora fallback logic
- lead capture
- project scope
- quote/planner pathways
- admin visibility

If preview fails, the journey must continue, not die.

9. FORM LOOP
All forms must:
- validate
- save meaningful structured data
- update lead/session state
- update Nexora context
- trigger next-step logic
- surface data to admin
- preserve progress where appropriate

10. CONTENT LOOP
Content, pages, CTAs, recommendations, and assistant prompts should pull from structured definitions where possible.
Do not hardcode disconnected copy and logic everywhere.

11. STATE LOOP
Critical state must persist properly across route changes.
Do not let the platform forget:
- journey stage
- intent
- selected service
- quote progress
- planner progress
- uploads
- prior recommendations
- unresolved blockers

12. CONVERSION LOOP
Every major page must have:
- a clear CTA
- a logical next step
- AI-aware recommendation
- a path into a commercial workflow

No dead ends allowed.
